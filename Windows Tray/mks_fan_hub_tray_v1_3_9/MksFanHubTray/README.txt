MKS Fan Hub Tray v1.3.9 — значок в трее + окно мониторинга и настройки хаба (заменяет mks_temp_feed)

ЧТО ДЕЛАЕТ
- сам находит плату на COM-портах, переподключается при обрыве, порт открывает без сброса платы;
- каждую секунду шлёт в плату TEMP=P102:..,GTX:..,CPU:..,SSD:.. (nvidia-smi + LibreHardwareMonitor);
- показывает температуры, вентиляторы (название, выход, %, датчик, тахо, RPM), режим платы, FAILSAFE;
- значок: зелёный = норма, жёлтый = предупреждение, красный = нет связи / плата не отвечает / FAILSAFE;
- уведомления при смене состояния (включаются в настройках), журнал MksFanHubTray.log рядом с exe.

КНОПКИ
- «Привязки…»  какой датчик (термистор или температура ПК) управляет каждым вентилятором.
               В режиме платы TMP-SRL GPU / вдув / выдув зафиксированы (так устроена прошивка);
               кнопка в диалоге переключает плату в TMP-MAN, где можно менять любой канал.
- «Кривые…»    5 точек «температура → %» на канал, график с красной линией текущей температуры.
               «Применить» — до перезагрузки платы; «Применить и сохранить» — запись в память платы.
               Температуры точек должны идти по возрастанию.
- «Меню»       настройки, показ скрытых строк, режим платы, автозапуск, журнал, выход.

КОНСОЛЬ И ТЕСТ ТАХОМЕТРОВ
- Внизу две вкладки: «Журнал» и «Консоль». Консоль — прокси к плате: можно ввести любую команду
  (Enter — отправить, ↑/↓ — история), ответы платы показываются как есть.
- Кнопки быстрых запросов: STATUS?, THERMS?, TACH?, CURVES?, BINDS?, MODE?. «Справка» — список команд
  и индексы каналов для SET. Фоновый обмен (температуры раз в секунду, опрос STATUS?) в консоль не попадает.
- «Тест тахо» (или Меню → «Тест тахометров») запускает TACHTEST: 3-pin вентиляторы на ~5 с на 100%,
  замер, возврат. Итог выводится по названиям каналов и пишется в журнал. Каналы, где вентилятор
  крутится, автоматически отмечаются подключёнными.
- SET=<индекс>,<%> плата принимает, но кривая канала перебивает значение примерно через секунду.
  Для удержания есть HOLD=<канал>,<%>[,<сек>] (прошивка 0.3.15+): кривая канал не трогает, по умолчанию
  30 с, максимум 300 с; HOLD=<канал>,OFF и HOLD=ALL,OFF снимают, HOLD? — список.
- Команды RESET и SAVE (CURVE=SAVE, BIND=RESET и т.п.) спрашивают подтверждение.

НОВОЕ В v1.3.9 - сохранение кривых стало проверяемым
- «Применить»: каждая точка уходит в плату, подтверждение платы сверяется с отправленным (при расхождении - до 3 повторов),
  потом кривые читаются с платы обратно и сверяются целиком; расхождения досылаются. Если плата упорно хранит не то - сообщение
  со списком точек и сохранение не выполняется.
- Раньше при «Применить» уходили все 5 точек канала, даже нетронутые, поэтому одиночный сбой связи мог испортить точку, которую ты не трогал.
  Теперь уходят только изменённые точки.
- В журнал пишется, что именно меняется: «Кривая FUN_DC_0, точка 1: 28°/25% -> 28°/2%» - любая неожиданная правка видна.
- Изменённые (ещё не применённые) поля в окне кривых подсвечены жёлтым.
- Колесо мыши над полями точек больше не меняет значения (случайная прокрутка могла менять % и температуры).
- В журнале при запуске указана версия программы.
- Текст окна «Связать…» напоминает: кривые всех связанных каналов станут такими же, как у текущего.

НОВОЕ В v1.3.8 (вместе с прошивкой 0.3.25)
- Связь кривых теперь можно делать между сколькими угодно каналами: если отмеченный канал уже состоит в группе,
  вся его группа сливается с группой текущего канала (раньше канал «переезжал» один, а прежние соседи выпадали).
  Пример: Fun_0+Fun_1 = гр. А, потом Fun_2 связываем с Fun_0 -> в гр. А все три.
- Прошивка 0.3.25: проверка остановки (100%) заканчивается за ~0,3 с, если вентилятор крутился с самого начала.

НОВОЕ В v1.3.7 (вместе с прошивкой 0.3.24) - автозапуск DC-вентиляторов
- Меню -> «Автозапуск DC-вентиляторов…»: у каждого DC-канала своя «точка раскрутки» (с какого % вентилятор стартует с места,
  по умолчанию 37%) и общие параметры: добавка (+5%), шаг и пауза снижения, как часто проверять остановку, число попыток (3).
  «Применить» действует сразу, «Применить и сохранить в плату» - ещё и переживёт перезагрузку платы.
- Как работает: если вентилятор остановился, плата ставит точку раскрутки + добавку на 2 с, потом снижает на шаг каждые
  N мс до нужных оборотов и проверяет, что он крутится. Не крутится - повтор; после заданного числа неудач подряд канал получает
  ОШИБКУ (выход 0%, в журнале «ОШИБКА: вентилятор … не раскрутился», значок красный). «Сбросить» в окне снимает ошибку.
- Остановку 3-pin вентилятора на частичном ШИМ по тахо не видно, поэтому плата раз в N секунд (60, 0 = выключено) на 0,7 с
  включает канал на 100% и считает импульсы. Это слегка слышно. Канал на 100% контролируется постоянно.
- Каналы, где вентилятор ни разу не крутился (нет импульсов), не проверяются и ошибку не выдают.
- «Проверить» в окне - принудительная проверка канала прямо сейчас (удобно проверить, придержав вентилятор рукой).
- Консоль: SPIN? / SPIN=… (справка).

НОВОЕ В v1.3.6 (вместе с прошивкой 0.3.23)
- Прошивка 0.3.23: запуск DC-вентиляторов толчком и нижний предел по кривой. Замер (31 Гц): стоп ~14%, старт ~37%.
  На DC-каналах значения кривой 1..19% поднимаются до 20% (0% = выключено). Если вентилятор стоит, а кривая просит
  меньше 45% - сначала 100% на 3 с, потом нужный %. Так же при включении платы. Только для значений из кривой:
  ручной режим («Ручное тестирование»), TACHTEST и FAILSAFE работают как раньше.
- В журнале: «Плата: DC-вентилятор … запускается толчком».

НОВОЕ В v1.3.5 (вместе с прошивкой 0.3.22) - подбор частоты ШИМ для каждого DC-канала
- Прошивка 0.3.22: все 4 DC-канала (D7/D8/D9/D10) гонит программный ШИМ из прерывания Timer2 (тик 4 кГц), у каждого
  канала своя частота 15..300 Гц, заводская - 31 Гц. Аппаратный ШИМ D9/D10 больше не используется (4-pin по-прежнему 25 кГц).
  Шаг заполнения = 100*Гц/4000 %, т.е. на 31 Гц ~0,8%, на 100 Гц ~2,5%, на 300 Гц ~7,5%.
- Ручное тестирование DC-канала: появился блок «Частота ШИМ канала». Число (15..300 Гц) или кнопка-пресет применяются на
  плате сразу (через ~0,25 с), без сохранения. «Всем DC-каналам» ставит выбранную частоту на все DC, «Заводская» - 31 Гц на все.
  «Сохранить частоты в плату» пишет частоты ВСЕХ DC-каналов в EEPROM (после перезагрузки платы остаются).
  Не сохранил - после сброса платы вернётся то, что было сохранено ранее (или 31 Гц).
- Если прошивка старая (нет DCFREQ), блок серый с подсказкой.
- Консоль: DCFREQ? / DCFREQ=<канал|ALL>,<Гц> / DCFREQ=SAVE / DCFREQ=RESET.
- Как подбирать: поставь вентилятор на 40-60% и крути частоту; шипение/писк уходит на низких частотах, но на очень низких
  (15-20 Гц) может появиться «пульсация» оборотов. Порог остановки/запуска тоже зависит от частоты - после подбора
  надо заново замерить, при каком % вентилятор останавливается и запускается.

НОВОЕ В v1.3
- Копирование и «склеивание» кривых (окно «Кривые…»):
    «Копировать на…» — разово скопировать кривую текущего канала на отмеченные каналы;
    «Связать…»      — связать каналы в группу: правка кривой любого из них меняет все (программа сама
                      отправляет в плату одинаковые кривые). Связи хранятся в MksFanHubTray.ini (Link.<канал>=<группа>),
                      в списке вентиляторов есть колонка «Кривая» («гр. A»). Снятая галочка в «Связать…» разрывает связь.
                      Если на плате кривые группы разошлись (кто-то менял их мимо программы), диалог предупредит;
                      любая правка выровняет группу.
- Свёрнутый режим (Настройки → «Связь с платой»): когда окно скрыто или свёрнуто, STATUS? идёт раз в 10 с,
  температуры — раз в 3 с (watchdog платы 8 с, поэтому не больше 6 с). Плата сама присылает события
  (прошивка 0.3.15+), так что важное не пропускается: событие вызывает немедленный опрос.
  Пульс EVENT=HB каждые 5 с служит признаком, что плата жива. При открытии окна — мгновенное обновление.
- События платы пишутся в журнал по-русски: перезагрузка, FAILSAFE вкл/выкл, смена режима, кнопка на плате,
  смена состояния термистора (только подключённых), окончание удержания.
- Сон Windows: перед сном связь приостанавливается (порт закрывается), после пробуждения через ~5 с плата
  ищется заново, датчики ПК (LibreHardwareMonitor) переоткрываются. Сразу после сна красные уведомления
  не показываются, пока связь восстанавливается. Плата при засыпании ПК обесточивается (12 В) —
  после пробуждения она стартует заново, вентиляторы 100% до первых температур.
- Меню → «Диагностика тахо…»: снятие «сырых» записей tach-пина 3-pin вентилятора на разных уровнях ШИМ
  в файл tachdump.log рядом с программой (нужна прошивка 0.3.15+):
    1) вентилятор крутится свободно — выбери канал, состояние «Крутится», уровни 100, 70, 50, 30 (сверху вниз:
       с места DC-вентилятор на 30–70% не стартует, поэтому сначала раскрутка на 100%) → «Снять записи».
       Снимай вентилятор по одному: канал с двумя вентиляторами (Exhaust 2,3) сначала проверь с одним
       отключённым, иначе сигналы двух вентиляторов смешиваются;
    2) придержи крыльчатку — состояние «Заблокирован», уровни 40, 70, 100 → «Снять записи»;
       повтори в 10+ разных положениях лопастей (в заметке пиши положение);
    3) пришли tachdump.log целиком. По нему подберём признак «вращается / стоит» при неполном ШИМ
       (для калибровки мёртвой точки и перезапуска зависших вентиляторов).
  Во время снятия канал удерживается на нужном уровне (кривая отключена, максимум 30 с), потом возвращается.
  Заблокированный вентилятор придерживай мягко и недолго: на каждый уровень уходит ~4 с.

НАЗВАНИЯ И «ПОДКЛЮЧЕНО / НЕ ПОДКЛЮЧЕНО»
- правый клик по строке (или F2) → «Переименовать…». Пустое название возвращает стандартное.
  Двойной клик по вентилятору открывает его кривую, по термистору — переименование.
- Подключённым считается канал/термистор, у которого есть своё название, ИЛИ который стабильно
  работал 20 секунд подряд (запоминается), ИЛИ отмечен вручную: правый клик → «Подключение».
  Один моргнувший отсчёт на пустом входе подключением не считается.
- 3-pin вентиляторы тахо показывают только при 100%, поэтому сами не определяются:
  дай им название или отметь «Подключён».
- Меню → Настройки: что делать с неподключёнными вентиляторами и термисторами —
  не показывать / показывать серым / показывать как есть (отдельно для каждых).
  Меню → «Показывать скрытые строки» временно показывает всё, чтобы до них добраться.
- Предупреждение (жёлтый значок) выдаётся только про подключённые: потерян датчик, вентилятор встал,
  канал привязан к датчику, которого нет, нет температуры ПК для канала.

СБОРКА (на машине с .NET 8 SDK)
  dotnet publish -c Release -r win-x64 --self-contained false -o publish
  (если на сервере нет .NET 8 Desktop Runtime — --self-contained true)
Запускать publish\MksFanHubTray.exe (запросит права администратора: нужны для датчиков CPU/SSD).
Автозапуск: Меню → «Запускать при входе в Windows» (задача планировщика, UAC при входе не будет).
