# fanhub-web — веб-интерфейс контроллера MKS Fan Hub (замена Windows-трея на Ubuntu)

Хаб по-прежнему сидит на USB-serial порту сервера, но вместо трея его обслуживает
этот сервис: кормит плату температурами (раз в 1 с), опрашивает `STATUS?` (раз в 2 с),
держит соединение и показывает всё в браузере. Прошивку менять не нужно — протокол 0.3.25
тот же, что в `Windows Tray/mks_fan_hub_tray_v1_3_9`.

## Температуры — напрямую, без Prometheus

- GPU (обе карты): NVML (`pynvml`, тот же источник, что у `nvidia-smi`)
- CPU: `/sys/class/hwmon`, чип `coretemp` (Package)
- NVMe: `/sys/class/hwmon`, чип `nvme` (Composite)

Никаких сетевых зависимостей: мониторинг может лежать целый день — вентиляторы этого
не заметят. Если датчик пропал, в плату уходит последнее известное значение
(плата сама уйдёт в FAILSAFE по своему watchdog, если данные совсем кончатся).

## Установка на сервере (Ubuntu)

```bash
sudo apt install -y python3.14-venv    # или python3-venv на других версиях Ubuntu
sudo usermod -aG dialout technic47     # доступ к /dev/ttyACM* (перелогиниться)
git clone <этот репозиторий> ~/fanhub-web # или скопировать папку fanhub-web
cd ~/fanhub-web
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
cp fanhub-web.service /etc/systemd/system/   # через sudo, см. ниже путь в unit
sudo systemctl daemon-reload
sudo systemctl enable --now fanhub-web
```

Веб-интерфейс: `http://<сервер>:8811`

## Возможности (актуальная версия)

- **Транспорт**: поиск платы (`AUTO`: все `/dev/ttyACM*`/`ttyUSB*`), переподключение
  при обрыве, открытие порта без сброса (HUPCL выключен — как `DtrEnable=false`
  в трее), опрос `STATUS?` раз в 2 с, кормление `TEMP=` раз в 1 с;
- **Мониторинг**: температура ПК (GPU/CPU/NVMe), термисторы, каналы (%, датчик,
  тахо, RPM, состояние автозапуска), FAILSAFE-баннер, журнал событий платы;
- **Каналы**: флаги «Подключён» (отключённые серые, не опрашиваются), фильтр
  «скрыть неподключённые», переименование каналов, привязка к датчику по клику;
- **Кривые**: редактор 5 точек с графиком и проверкой записи чтением;
  **группировка** — одна кривая на несколько выводов: владелец (первый канал
  по порядку платы) редактирует общую кривую, у остальных членов редактор
  в режиме просмотра; при группировке кривая владельца копируется всем членам;
- **Сервис**: ручной режим (ползунок + HOLD), тест тахо, настройки SPIN и
  DCFREQ;
- **Консоль**: прокси-командная строка к плате прямо в браузере;
- **Термисторы**: флаги «Подключён» + фильтр, как у каналов.

## API (кратко)

- `GET /api/status` — снапшот платы + `disabled_channels`, `disabled_thermistors`, `curve_groups`;
- `GET/POST /api/curves` — чтение/запись кривых (запись fan-out'ится на всю группу);
- `POST /api/curve-group` `{channel, with}` — группировка (`with:""` — открепить);
- `POST /api/channel`, `POST /api/therm` — флаги «Подключён»;
- `POST /api/channel-name`, `POST /api/bind`, `POST /api/mode`, `POST /api/spin`,
  `POST /api/dcfreq`, `POST /api/tach-test`;
- `WS /ws` — живые обновления статуса;
- `GET/POST /api/console` — прокси команд к плате.

Полный список — в `fanhub_web/server.py`.

## Не делаем (осознанно)

- Экспорт телеметрии в Prometheus — датчики читаются напрямую, веб-интерфейс
  самодостаточен;
- Графики истории в вебе — для этого есть Grafana в инфраструктурном проекте.

## Тест без железа

Эмулятор платы из трея: `Windows Tray/mks_fan_hub_tray_v1_3_9/MksFanHubTray/test/fake_board.py`
(POSIX-терминал). Соединить через псевдотерминалы:

```bash
socat -d -d PTY,raw,echo=0,b115200 PTY,raw,echo=0,b115200 &
# один конец — эмулятор, другой указать в config.json: "port": "/dev/pts/N"
```
